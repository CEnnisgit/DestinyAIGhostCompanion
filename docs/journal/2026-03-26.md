# 2026-03-26 — Phase 1.5: Tenant Foundation + Dashboard UI + Stack Decision

## Context

Returning after a hiatus. Completed the after-implementation documentation upgrade (job-engine, event-history, architecture overview) and the Phase 2 implementation matrix. GPS1 and GPS2 form fields are now fully extracted.

## How Today Evolved

Started with Phase 1 dev dashboard validation (Jobs page, icon rail). While wiring the Jobs UI, the missing `jobs`/`job_events` tables surfaced questions about schema provisioning and tenant data isolation.

That led to ADR-0020 (DB isolation strategy), then a deep-dive into what "tenant portfolio" actually means. Through domain research with real-world LMP workflow evidence, we discovered that the old `TenantAsset(FirmID, BIN)` model was wrong — the real relationship unit is the **client**, not the building. This resulted in a complete redesign of the Phase 1.5 scope.

After design, we implemented the full tenant foundation (domain, DB, API, migration), wrote 16 unit tests, verified all 7 API endpoints, then moved into UX design discussion for the job creation flow (ADR-0023: Address-First Job Creation). Finally, built the Portfolio page in the dev dashboard with Clients + Saved Buildings tabs, and wrapped up with a full frontend stack decision (ADR-0024).
