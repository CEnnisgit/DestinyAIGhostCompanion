# Password Policy Specification

**Module:** `Auth`
**Type:** Policy
**Source of Truth:** `pcd-domain/src/auth/password.rs`
**Version:** 1.0.0
**SFR:** SNFR-SC-11 (Password storage — Argon2)

---

## 1. Overview

PCD stores passwords using Argon2id, the current recommended algorithm for password hashing (winner of the Password Hashing Competition, recommended by OWASP). This spec defines the hashing configuration, storage format, and verification behavior.

---

## 2. Algorithm: Argon2id

| Parameter | Value | Why |
|-----------|-------|-----|
| **Variant** | Argon2id | Hybrid — resistant to both side-channel and GPU attacks |
| **Memory** | 19 MiB (19456 KiB) | OWASP minimum recommendation |
| **Iterations** | 2 | OWASP recommendation for 19 MiB memory |
| **Parallelism** | 1 | Single-threaded hashing (safe for async context) |
| **Salt** | 16 bytes, random per hash | Auto-generated by the `argon2` crate |
| **Output** | PHC string format | Self-describing, includes algorithm + params + salt + hash |

### Crate Usage

```rust
use argon2::{
    password_hash::{PasswordHash, PasswordHasher, PasswordVerifier, SaltString},
    Argon2, Algorithm, Params, Version,
};
use rand::rngs::OsRng;

/// Hash a plaintext password for storage.
pub fn hash_password(password: &str) -> Result<String, AuthError> {
    let salt = SaltString::generate(&mut OsRng);
    let params = Params::new(19456, 2, 1, None)
        .map_err(|_| AuthError::HashingFailed)?;
    let argon2 = Argon2::new(Algorithm::Argon2id, Version::V0x13, params);

    argon2
        .hash_password(password.as_bytes(), &salt)
        .map(|hash| hash.to_string())
        .map_err(|_| AuthError::HashingFailed)
}

/// Verify a plaintext password against a stored hash.
pub fn verify_password(password: &str, hash: &str) -> Result<bool, AuthError> {
    let parsed_hash = PasswordHash::new(hash)
        .map_err(|_| AuthError::InvalidHash)?;

    Ok(Argon2::default()
        .verify_password(password.as_bytes(), &parsed_hash)
        .is_ok())
}
```

### Stored Format (PHC String)

```
$argon2id$v=19$m=19456,t=2,p=1$c29tZXNhbHQ$WV...hash...
```

This is self-describing — the algorithm, version, parameters, salt, and hash are all encoded in the string. No separate columns for salt or algorithm are needed.

## 3. Storage

```sql
ALTER TABLE users ADD COLUMN password_hash TEXT;
```

| Property | Value |
|----------|-------|
| **Column** | `users.password_hash` |
| **Type** | `TEXT` (nullable) |
| **Nullable?** | Yes |

### Why Nullable

- Future OAuth/SSO users may not have a password
- Future passkey users may not have a password
- The column being NULL means "this user cannot log in with a password" — not "this user doesn't exist"

### Login Guard

```rust
// In login flow:
match user.password_hash {
    Some(hash) => verify_password(&input.password, &hash)?,
    None => return Err(AuthError::InvalidCredentials), // no password set
}
```

---

## 4. Enumeration Prevention

When login fails, the API returns a constant error regardless of the failure reason:

```json
{ "error": "invalid_credentials" }
```

**Timing attack prevention:** If the email doesn't exist, we still run a dummy Argon2 verification to ensure the response time is consistent:

```rust
// Pseudo-code:
let user = find_user_by_email(&email).await;

match user {
    Some(u) => {
        // Real verification
        if !verify_password(&password, &u.password_hash)? {
            return Err(AuthError::InvalidCredentials);
        }
    }
    None => {
        // Dummy hash to consume the same time
        let _ = verify_password(&password, &DUMMY_HASH);
        return Err(AuthError::InvalidCredentials);
    }
}
```

The `DUMMY_HASH` is a pre-computed Argon2id hash with the same parameters. This ensures an attacker cannot distinguish "email not found" from "wrong password" based on response timing.

## 5. Alpha Considerations

| Item | Alpha Approach |
|------|----------------|
| **Account creation** | Admin seeds accounts with pre-hashed passwords |
| **Password requirements** | None enforced for alpha (seeded accounts) |
| **Password change** | Not implemented for alpha |
| **Password reset** | Not implemented for alpha (SFR-SRAN-03 deferred) |
| **Password strength rules** | Deferred — define when self-registration is built |
